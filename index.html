How it works

Three steps, no infrastructure.

State lives where your code already lives: in git. Any host works.

  1. 01

    Install & launch

    Zero infrastructure needed.

    Install @skepagent/skep from npm. Run bare skep in any repo to open your local agent CLI (claude, codex or pi). Run skepd as a per-device service when you want the blackboard.

  2. 02

    Decentralized git blackboard

    State lives where code lives.

    Every state change is one JSON event in one SSH-signed commit on the blackboard repo's main. Each device replays the log with a deterministic reducer, so devices at the same tip agree on who owns what without ever talking to each other.

  3. 03

    Live & async pairing

    Work locally, hand off globally.

    Use skep session start / join for an in-memory session across your LAN, or let skepd plan, claim and execute work in the background and publish it as stacked pull requests.

Architecture

A daemon per device. A git repo in the middle.

The human drives skep. Each device runs one skepd that only makes outbound connections to your git remote. There is no coordinator to run or trust.

architecture.txt
 human ──► skep (CLI) ──unix socket──► skepd (one per device)
                                         ├─ sync: fetch → reducer → state
                                         ├─ publisher: single writer, signed
                                         ├─ heartbeats: hb/<agent> refs
                                         └─ slots: plan · review · claim · execute
                                               └─ agent CLI in a worktree
                                                     └─ checks → push → stacked PR

 blackboard repo (main = signed log) ◄──► every device's skepd
 code repo (branches, PRs)           ◄──► executing devices
  • Deterministic code enforces the protocol. Models only produce content: plans, reviews and code. Daemons validate, authorize, sequence, test, sign and publish.
  • No inbound connectivity (D18). Blackboard devices never connect to each other. No mesh VPN or fixed IP is required.
  • Human holds the gates. You create tasks, approve plans, revoke leases, decide escalations and merge.
  • Single-agent fast path by default. Team mode with several items, peer review and stacked PRs only when the task needs it.

Features

Built for agents that don't share a machine.

Signed git blackboard

Commits as event logs. Every task, plan, lease and delivery is an SSH-signed event, verified against each device's local allowed_signers. Forged or unsigned commits become no-ops and raise an alarm.

Dual-mode execution

Use bare skep to open your local agent interactively. Use the skepd daemon for background plan, review, claim and execute slots across devices.

In-memory session TUI

Start a session on your workstation, join from your laptop with a 12-digit code, and watch peers, items and agent state in skep ui.

D19 credential isolation

Zero secret sharing. Each device's agent CLI uses its own local login. Keys never touch git or the wire, not even as a hash or a label.

Epoch-fenced leases

A claim bumps the work item's epoch, and every downstream event and branch is fenced by it. A laptop that wakes from sleep after its lease was revoked can never deliver stale work.

Native CLI tooling

A pure Node.js + TypeScript CLI with four runtime dependencies: commander, zod, smol-toml and yaml. It starts fast and stays small.

Security

Security by architecture, not policy.

Decision D19

“Skep never transports, stores, syncs or brokers provider credentials, API keys or provider configurations between devices, in any form: not as plaintext, not as ciphertext, not as a hash, and not as a label.”

⇄

  • SSH-signed event chain

    Every blackboard commit is signed with an SSH key and checked against a trust root that each device installs locally. Fingerprints are compared out of band at skep init.

  • Strict no-credential sync

    Other agent tools sync config and keys across devices. Skep explicitly forbids it. Machine A uses its Claude login and machine B uses its Codex login, and Skep never reads or records either.

  • Auditable history

    When an agent makes a mistake, git log on the blackboard shows exactly which device, key and event made each step. The genesis commit is human-signed.

  • No auto-merge, ever

    Plan approval, lease revocation, escalation decisions and merges stay with you. In session mode the master gets a redacted summary, and the full transcript stays on the device that did the work.

Quickstart

Up and running in 60 seconds.

Needs Node.js ≥ 22.12, git ≥ 2.34, OpenSSH ≥ 8.9, and an agent CLI that is already logged in on each device.

# 1. Install globally (bins: skep, skepd)
npm install -g @skepagent/skep
# 2. Launch your local agent (claude, else codex, else pi)
skep
# or pick one explicitly
skep tui --agent codex
# 3. Start a multi-device live session (prints a join code)
skep session start
skep ui

# 4. Join from a second device on the same network
skep session join --code <join-code> --host <master-ip>:7419 --ui

# send work to the session
skep session intent "what should be done"
# 5. Blackboard mode: one empty private git repo + skepd on every device
skep init                 # per device: daemon key + allowed_signers line
skep init --genesis --human-key <path>   # controller only, once
skepd                     # run as a service (systemd / launchd)
skep doctor

skep task new "…" --repo <allowlist-name> --owner <agent>
skep plan approve <task>
skep status

Full trust setup, revoke and re-genesis steps are in the runbook.
